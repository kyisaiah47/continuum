## Visual Identity

### Color System

**Primary Colors:**
```
Near-Black:        #0D0E12  — Primary backgrounds
Elevated Black:    #16171D  — Card surfaces, code blocks
Dark Graphite:     #1E1F26  — Hover states
```

**Accent Gradient: Iridescent Thread**
```
Cyan:              #00D4FF  — Data input nodes
Purple:            #8B5CF6  — Processing/validation
Pink:              #FF7AE0  — Output/completion
```
*Applied as thin animated lines representing data flow*

**Neutrals:**
```
Pure White:        #FFFFFF  — Primary text
Technical Gray:    #A1A3A8  — Secondary text, labels
Border Gray:       #2A2B32  — Dividers, boundaries
```

**Glow Effects:**
```
Cyan Glow:         #00D4FF at 20% opacity
Purple Glow:       #8B5CF6 at 20% opacity
Pink Glow:         #FF7AE0 at 20% opacity
```

**Color Psychology:**
- Near-black = depth, foundation, underlying infrastructure
- Iridescent gradient = data transformation, flow, continuous process
- Glows = energy, verification, network activity

### Typography

**Primary Pairing:** IBM Plex Mono + Inter Light

**IBM Plex Mono:**
- For code, addresses, hashes, block numbers
- Monospace credibility
- Technical authenticity

**Inter Light:**
- For headlines and body text
- Balances technical precision with readability
- Harmonizes with Myn and Ethos

**Weight Usage:**
- Light (300): Body text, descriptions
- Regular (400): UI labels, navigation
- Mono Regular: All technical data
- Semibold (600): Section headers (sparingly)

**Style Guidelines:**
- ALL-CAPS for micro-labels (technical context)
- Sentence case for documentation prose
- Strict hierarchical spacing
- Generous whitespace around code blocks

**Example Hierarchy:**
```
Section Header (14px, ALL-CAPS, Letter-spacing +0.1em): "NETWORK STATUS"
Metric (48px, Light):                                   "99.97%"
Metric Label (16px, Regular):                           "Network Integrity"
Code Block (14px, Mono):                                "continuum::verify_consent()"
Block Number (16px, Mono):                              "#4,829,301"
Hash (12px, Mono):                                      "0x4f8a2bc7...d92c1e45"
```

```css
cubic-bezier(0.16, 1, 0.3, 1) — Smooth, architectural
```

**Timing:**
- Micro-interactions: 300ms
- Network updates: Stagger by 100ms per item
- Gradient flow: 4000ms continuous loop
- Page transitions: 500ms ease-in-out

**Animation Types:**
- **Network particles:** Subtle ambient motion (always-on)
- **Waveform visualization:** Represents data flowing through protocol

**Motion Philosophy:**
Continuous, elemental, infrastructural. Animations represent real network activity, not decorative flourishes.

### How It Works (Technical Flow)

```
1. Consent Grant
   User approves data request via Myn app.
   Approval signed with user's private key.

2. On-Chain Verification
   Signature verified by Continuum smart contract.
   Consent details recorded on Polkadot parachain.

3. Time-Limited Access
   Organization can access data for specified duration.
   Payment held in escrow, released upon verification.

4. Audit & Enforcement
   All actions recorded immutably.
   Revocation enforced automatically.
   Full transparency for all parties.
```

## Differentiation

### What Makes Continuum Different

**vs. Traditional Databases:**
Continuum is immutable and decentralized. No single entity controls the records.

**vs. Other Blockchains:**
Purpose-built for consent verification. Optimized for privacy, not just financial transactions.

**vs. Consent Management Platforms:**
Cryptographic proof, not just logged checkboxes. Verifiable by any party.
